# LEC09 Sonic 애니메이션 뷰어 — 개발 PRD

## 1. 문서 개요

| 항목                    | 내용                   |
| ----------------------- | ---------------------- |
| 제품                    | Sonic 애니메이션 뷰어  |
| 기준 기획               | `PRE-PRD.md`         |
| 구현 언어 / 라이브러리  | Python /`pico2d`     |
| 실행 프로그램           | `sonic_animation.py` |
| 입력 이미지             | `sonic-sprite.png`   |
| 실행 파일과 이미지 위치 | `Labs/LEC09/`        |

이 문서는 기획 초안을 개발·검증 가능한 요구사항으로 정리한다. 스프라이트 시트에 실제로 들어 있는 동작과 프레임 좌표는 이미지 분석 후 확정하며, 문서만으로 알 수 없는 값을 임의로 만들어내지 않는다.

## 2. 제품 설명

사용자가 프로그램을 실행하면 Sonic 스프라이트 시트에서 식별한 애니메이션 동작을 한 번에 하나씩 보여준다. 현재 동작의 프레임을 차례로 재생하는 것을 한 회로 세며, 한 동작을 5회 재생한 뒤 1초 동안 쉰다. 이어 다음 동작을 같은 방식으로 재생하고, 마지막 동작 다음에는 첫 동작부터 이 순서를 계속 반복한다. 캐릭터는 화면에서 알아보기 쉬운 크기로 표시한다.

## 3. 사용자와 사용 흐름

**대상 사용자:** 수업 과제의 결과를 실행해 Sonic 스프라이트 애니메이션을 확인하는 학습자.

**기본 흐름**

1. 사용자가 `Labs/LEC09/sonic_animation.py`를 실행한다.
2. 프로그램이 `sonic-sprite.png`를 읽는다.
3. 스프라이트 시트에서 식별한 첫 애니메이션의 프레임 재생을 시작한다.
4. 해당 동작의 전체 프레임 재생을 5회 완료한다.
5. 1초 쉰 다음 목록의 다음 동작으로 넘어간다.
6. 마지막 동작의 대기 시간이 끝나면 첫 동작으로 돌아간다.
7. 사용자가 프로그램 창을 닫으면 실행을 끝낸다.

## 4. 제품 목표와 완료 정의

제품은 다음 조건을 모두 만족할 때 완료로 본다.

- 지정된 기술, 소스 파일명 및 스프라이트 이미지로 실행된다.
- 이미지에서 확인되는 모든 애니메이션 동작을 실제 프레임에 근거해 재생한다.
- 각 동작의 5회 반복, 1초 대기, 동작 순환 규칙을 정확히 지킨다.
- 캐릭터가 원본 비율을 유지하며 화면에서 알아보기 쉬운 크기로 보인다.
- 최소 20개의 의미 있는 개발 커밋으로 작업 과정을 나눈다.
- 아래 수용 기준을 실제 실행 결과로 확인한다.

## 5. 제품 범위

### 포함

- `pico2d` 창을 사용한 애니메이션 표시
- `sonic-sprite.png` 로드
- 스프라이트 시트 분석을 바탕으로 한 프레임 영역 및 순서 정의
- 동작별 프레임 재생, 5회 반복, 동작 간 1초 대기
- 애니메이션 목록의 끝에서 처음으로 돌아가는 무한 재생
- 화면에서 식별 가능한 크기로 확대해 표시
- 창 닫기 시 프로그램 종료

### 제외

- 게임 조작, 캐릭터 이동, 충돌 및 게임 규칙
- 키보드로 애니메이션을 고르거나 재생을 제어하는 기능
- 스프라이트 편집, 프레임 추출 도구 또는 재생 목록 편집 UI
- 기획에 지정되지 않은 별도 그래픽 에셋이나 시각 효과 제작

## 6. 기능 요구사항

### FR-1. 실행 및 리소스 로드

- 프로그램의 실행 소스는 `Labs/LEC09/sonic_animation.py` 한 파일로 한다.
- 프로그램은 같은 과제 폴더의 `sonic-sprite.png`를 애니메이션 원본으로 사용한다.
- 실행 위치가 달라져도 에셋을 찾을 수 있도록 파일 위치를 기준으로 경로를 구성한다.
- 이미지 로드에 실패하면 원인을 확인할 수 있게 오류를 알리고 정상적인 종료 경로로 빠져나온다. 이미지를 읽지 못한 상태에서 재생을 계속하지 않는다.

### FR-2. 스프라이트 시트 분석 및 프레임 데이터

- 구현자는 코드를 작성하기 전에 시트의 실제 크기와 배치를 확인한다.
- 캐릭터 동작별로 프레임 영역, 프레임 수, 프레임 순서를 식별한다.
- 재생 목록에는 연속 프레임으로 이루어진 애니메이션 동작만 포함한다. 제목, 크레딧, 장식 또는 단일 정지 이미지는 동작으로 재생하지 않는다.
- 분석된 프레임 데이터는 `sonic_animation.py`에서 동작별로 검토·수정하기 쉬운 형태로 정의한다.
- 프레임 경계나 순서가 불확실하면 확인 없이 확정하지 않는다. 시트와 실제 출력 결과를 대조해 결정한다.

### FR-3. 한 동작의 프레임 재생

- 한 회 재생은 해당 동작의 첫 프레임부터 마지막 프레임까지 정의된 순서대로 한 번 진행하는 것을 뜻한다.
- 한 동작의 프레임이 끝나면 같은 동작의 첫 프레임으로 돌아가 다음 회를 시작한다.
- 동작별 프레임 전환 속도는 실행 중 일관되게 유지한다. 기획에서 수치를 정하지 않았으므로 구현 시 화면에서 자연스럽게 보이는 값을 확인해 정하고, 코드에서 쉽게 조정할 수 있도록 관리한다.
- 프레임을 그릴 때 이전 프레임의 잔상이 남지 않도록 화면을 갱신한다.

### FR-4. 동작 반복 및 순서

- 한 동작은 전체 프레임 재생을 정확히 5회 완료해야 다음 상태로 이동한다.
- 다섯 번째 재생을 마친 후 동작 사이 대기 상태에 들어간다.
- 대기 상태는 1초 동안 지속된 다음 재생 목록의 다음 동작을 선택한다.
- 동작 순서는 시트 분석으로 작성한 재생 목록의 순서를 따른다.
- 마지막 동작도 5회 재생 후 1초 대기한다. 대기가 끝나면 재생 목록의 첫 동작으로 이동한다.
- 대기 시간과 반복 횟수는 코드에서 확인하고 변경하기 쉬운 값으로 관리한다.

### FR-5. 확대 표시

- 애플리케이션 창의 기본 크기는 약 1200×800 픽셀로 설정한다.
- 캐릭터는 원본보다 크게 표시되어 화면에서 알아보기 쉬워야 한다.
- 확대 시 프레임의 가로세로 비율을 보존한다.
- 프레임이 화면 밖으로 잘리거나 다른 프레임의 일부가 섞여 보이지 않도록 시트의 경계와 표시 위치를 확인한다.
- 캐릭터의 확대 배율과 위치는 약 1200×800 픽셀 창 안에서 프레임이 잘리지 않고 보기 좋도록 정한다.

### FR-6. 종료

- 창 닫기 요청을 받으면 반복 재생을 멈추고 프로그램을 종료한다.
- 정상 종료 시 사용한 `pico2d` 그래픽 자원을 정리한다.

## 7. 재생 상태와 전이 규칙

| 현재 상태        | 완료 조건                                             | 다음 상태             |
| ---------------- | ----------------------------------------------------- | --------------------- |
| 동작 프레임 재생 | 현재 동작의 프레임 한 바퀴 완료, 반복 횟수가 5회 미만 | 같은 동작의 다음 회   |
| 동작 프레임 재생 | 현재 동작의 프레임 한 바퀴 완료, 반복 횟수가 5회      | 1초 대기              |
| 1초 대기         | 대기 시간 1초 경과, 다음 동작이 존재                  | 다음 동작의 첫 프레임 |
| 1초 대기         | 대기 시간 1초 경과, 현재 동작이 마지막                | 첫 동작의 첫 프레임   |
| 모든 실행 상태   | 창 닫기 요청                                          | 자원 정리 후 종료     |

각 동작을 시작할 때 프레임 인덱스와 해당 동작의 반복 횟수를 초기화한다. 한 동작의 상태가 다음 동작으로 넘어갈 때 이전 동작의 프레임 인덱스나 반복 횟수를 이어받지 않는다.

## 8. 비기능 요구사항 및 제약

- Python과 `pico2d`를 사용한다.
- 실행 로직은 `sonic_animation.py` 단일 파일에 둔다.
- 입력 이미지 `sonic-sprite.png`를 수정하지 않는다.
- 반복 재생과 대기는 실행 시간 기준으로 동작해야 하며, 대기 중에도 창 닫기 요청을 처리할 수 있어야 한다.
- 구현은 기능을 검토 가능한 작은 단계로 나누되, 커밋마다 사용자에게 확인 가능한 코드·검증·문서 변경을 포함한다.
- 의미 없는 파일 변경이나 쪼개기만으로 커밋 수를 채우지 않는다.
- 모든 Git 커밋 메시지는 반드시 한글로 작성한다.

## 10. 구현 및 커밋 계획

| 확대 과정에서 비율 왜곡이나 화면 잘림이 생길 수 있음                | 원본 비율 유지 및 실제 창에서 대표 프레임을 점검한다.                                  |

## 12. 기획에서 정하지 않은 구현값

다음 값은 `PRE-PRD.md`에 수치나 구체 목록이 없으므로 이미지 분석과 실행 확인 후 정한다. 결정된 값은 코드에서 찾기 쉽도록 관리하고, 확인된 결과를 프레임 데이터에 반영한다.

- 애니메이션 동작의 이름, 개수, 재생 순서
- 각 동작의 프레임 좌표와 프레임 수
- 프레임 전환 속도
- 배경색, 캐릭터 위치 및 확대 배율 (약 1200×800 픽셀 창에서 시각적으로 확인해 정함)
